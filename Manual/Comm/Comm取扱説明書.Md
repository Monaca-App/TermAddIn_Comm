## 1. 機能概要と基礎知識（はじめての方へ）

### 対応する機能の概要
**Comm（RS-232C / UART シリアル通信）** アドインは、パソコンと外部機器を **シリアルケーブル（RS-232C ケーブルや USB-シリアル変換ケーブル）** で 1 対 1 に繋ぎ、文字コマンド・バイナリ電文・外部テキストファイルの送受信、および応答プロンプト待機による自動制御を行うための基本通信機能です。
温調器・電子天秤・バーコードリーダ・マイコンボード・RS-232C 端子付きの旧型計測器など、**「文字を送ると返事が返ってくる」** 機器全般に対応します。

### 機能の実現方法
* **OS 標準シリアル API ＋ 排他セッション制御**: `.NET Framework 4.8` 標準のシリアル通信基盤と専用リングバッファを用い、外部の有償シリアルドライバを追加することなく安定した送受信を実現します。
* **Excel マクロ（CSV シーケンス）からの 1 行制御**: プロパティ画面で COM ポートやボーレートを設定し、シート上のコマンド（`Com_Open` ➔ `Com_Send` ➔ `Com_WaitPrompt` ➔ `Com_Close`）を並べるだけで自動化できます。
* **実機不要の検証経路**: `c2c`（ドライバ不要の仮想ヌルモデム）や `TermEmulator` の仮想 COM ポートと自動連携し、ケーブルや実機がない机上でも全手順を事前テストできます。

### このアドインを選択することの利点
* **プログラミング不要で即自動化**: VBA や C# でシリアルポート開閉・受信バッファ監視・タイムアウト処理を一から組む必要がなく、Excel 表の記述だけで検査手順を作れます。
* **文字化け・取りこぼしを防ぐ安全設計**: 改行コード（`CRLF`/`CR`/`LF`）やプロンプト待機（アイドルリセット方式のタイムアウト・ラベル分岐）をエンジン側が吸収するため、現場での通信トラブルを抑えられます。
* **仮想 COM による事前デバッグ**: 実機を借りられない設計段階でも、`c2c` / `TermEmulator` でエラー応答や無応答タイムアウトの分岐まで検証できます。

### 設定の妥当性を判断するためのチェックポイント
シリアル通信は **「パソコン側と相手機器側の 5 つの条件が 1 つでも食い違うと、文字化けしたり一切通信できなくなったりする」** のが最大の特徴です。プロパティ画面を開く前に、相手機器のマニュアルや本体設定画面で以下を確認してください。

| 確認項目 | 項目の意味 | 設定値の目安・確認方法 |
| :--- | :--- | :--- |
| **COM ポート番号** | パソコンのどの差込口に繋がっているか（例: `COM3`） | Windows の「デバイスマネージャー」➔「ポート (COM と LPT)」で、USB 変換ケーブルを抜き差しして増減する番号を確認します。 |
| **通信速度（ボーレート）** | 1 秒間に送るデータの速さ（単位: bps） | 相手機器と **完全一致** が必須です。一般的な機器は `9600` または `115200` が最も多く使われます。 |
| **データビット / パリティ / ストップビット** | 1 文字を送るときの「区切り方と誤りチェックの約束」 | 一般的な計測器・マイコンは **`8 / None / 1`**（8N1）、旧来の工場機器は **`7 / Even / 1`**（7E1）が多く使われます。 |
| **改行コード（デリミタ）** | 「ここで 1 つの命令が終わり」と伝える合図 | 機器によって `CRLF`（`\r\n`）、`CR`（`\r`）、`LF`（`\n`）が異なります。反応がないときはまずここを疑います。 |
| **フロー制御** | 受信側の処理が追いつかない場合に送信を一時停止・再開する制御方式 | 最近の機器や短いコマンドではほとんど不要です。まずは **`なし`** で試し、マニュアルに指定がある場合のみ変更します。 |

### 通信の仕組み解説（プロトコル構造と代表的なトラブル事例・対処法）
RS-232C（UART）では、1 文字ごとに以下の「枠組み」で電気信号が 1 ビットずつ送られます。

```text
[スタート(1bit)] + [データ本体(7 or 8bit)] + [パリティ(なし/偶/奇)] + [ストップ(1 or 2bit)]
```

* **事例①：文字化けする** ➔ ボーレート（例: `9600` と `115200`）またはデータ長・パリティ（`8N1` と `7E1`）が相手機器と食い違っています。
* **事例②：コマンドを送っても返事がない** ➔ 末尾の改行コード（`CR` / `LF` / `CRLF`）が機器の期待と異なるか、RS-232C ケーブルの種別（ストレート／クロス）が逆になっているケースが大半です。
* **事例③：COM ポートが開けない** ➔ 別のソフト（Tera Term やメーカー製ユーティリティ等）が同じ COM ポートを占有したままになっています。他ソフトを閉じてから再実行してください。

## 2. プロパティ設定画面：「通信ポート」タブの詳細

メイン画面で **`RS-232C`** モードを選択しているときに表示され、[`Com_Open`](./Com_Open.Md) 等のシリアル通信条件を設定します（`Comm` セクションへ保存）。

※ 画面全体の構成および「コマンド集」タブの共通操作・`[OK]` 1 タブ保存ルールについては、[プロパティ設定画面取扱説明書（共通）](../プロパティ設定画面取扱説明書.Md) を参照してください。

| 項目名 | 設定値・範囲（既定値） | 詳しい意味と設定のポイント |
| :--- | :--- | :--- |
| **`ポート`** | 物理 COM / `c2c`・`TermEmulator` 仮想 COM / `COM1`〜`COM16`（直接入力可） | 接続先のシリアルポート名を選びます。`c2c` や `TermEmulator` のドライバレス仮想 COM が稼働中の場合は、そのポート名（例: `COM10`、`COM20`）が自動で候補へ追加されます。 |
| **`通信速度`** | `1200`〜`460800` bps（代表値: `9600`, `115200`） | 相手機器のボーレート（bps）に合わせます。 |
| **`データビット`** | `5` / `6` / `7` / `8`（一般機器は `8`） | 1 文字あたりのデータビット長です。一般的な計測器・マイコンは `8`、旧来の PLC 計算機リンク等では `7` が多く使われます。 |
| **`パリティ`** | `None` / `Even` / `Odd` / `Mark` / `Space` | 誤り検出ビットの方式です（一般機器は `None`、PLC 系は `Even` が多く使われます）。 |
| **`ストップビット`** | `One` / `OnePointFive` / `Two` | 1 文字終端のストップビット長です（通常は `One`）。 |
| **`応答待ち時間`** | `0`〜`20` 秒（既定 `3` 秒）＋ `自動調整` チェック | `Com_WaitPrompt` 等のプロンプト待機コマンドがタイムアウトするまでの秒数です。`自動調整` を ON にすると、タイムアウト発生時に待ち時間を自動加算して再試行しやすくします。 |
| **`エコー`** | `なし` / `あり` | ターミナル画面で入力した文字をローカル側でもエコー表示するかどうかを選びます（相手機器がエコーバックしない場合に `あり` にします）。 |
| **`フロー制御`** | `なし` / `Xon/Xoff` / `RTS` / `Xon/RTS` | 相手機器のハードウェア／ソフトウェアフロー制御仕様に合わせます（迷った場合はまず `なし` から試してください）。 |

### 設定手順の例（CSV 登録 ＋ `COM10` 設定）
`[OK]` は表示中 1 タブのみ保存するため、以下の 2 ステップで行います。
1. **ステップ 1（コマンド集の登録）**: プロパティの **「コマンド集」** タブで **`コマンド追加`** ➔ ファイル種類を **`すべてのファイル (*.*)`** に変えて `.csv` を選択 ➔ **`[ ↑ ]`** で上段へ移動 ➔ **`[OK]`** で保存。
2. **ステップ 2（通信ポートの設定）**: 再度プロパティを開いて **「通信ポート」** タブへ切り替え、`ポート` に **`COM10`** 、`通信速度` に **`9600`** を選択して **`[OK]`** で保存。

## 3. 実機なしテスト（`c2c` / `TermEmulator` 仮想 COM 連携）

* **[c2c](https://github.com/Monaca-App/c2c/blob/main/Manual/c2c操作説明書.Md)**（ドライバ不要仮想ヌルモデム）で作成した仮想 COM ペア（例: `COM10 ⇔ COM11`）、または **[TermEmulator](https://github.com/Monaca-App/TermEmulator/blob/main/Manual/TermEmulator操作説明書.Md)** のドライバレス仮想 COM モード（例: `COM20`）が稼働中の場合、「通信ポート」タブの `ポート` 一覧へ自動表示されます。
* 実機シリアル機器がない環境でも、SCPI 計測器プリセットや自動応答ルール・異常注入（遅延／無応答／分割等）と組み合わせて `Com_*` シーケンスを検証できます。

## 4. マクロコマンド一覧（全 6 コマンド）

* **[Com_Open](./Com_Open.Md)** / **[Com_Close](./Com_Close.Md)**
  * **概要**: PC アプリ環境設定（UI）または引数指定の通信条件（最大 5 引数）で COM ポートをオープンして排他セッションを確立（`Com_Open`、他ドメイン稼働時は自動クローズ切替）、または切断・解放（`Com_Close`）します。`PortName` に空文字 `""` を渡すか省略した場合はプロパティ設定画面のポート番号を継承します。
  * **書式**:  
    `,SEQUENCE, [ステップキー], Com_Open, "[PortName(任意)]", [BaudRate(任意: 9600)], "[Parity(任意: None)]", [DataBits(任意: 8)], "[StopBits(任意: 1)]"`  
    `,SEQUENCE, [ステップキー], Com_Close`
* **[Com_Mode](./Com_Mode.Md)**
  * **概要**: UART 通信条件（`"Baud,Parity,DataBits,StopBits"`）、フロー制御（`"NONE"` / `"RTSCTS"` / `"XONXOFF"` / `"RTSXON"`［`"BOTH"`］）、送信終端デリミタ（`"TXCRLF"` / `"TXCR"` / `"NON"`；※LF 単体を設定する場合は 2 引数個別指定 `"LineEnding", "LF"` または `Com_Send` 側の改行指定 `"LF"` を使用）、および受信データモード（`"ASCII"` / `"BIN"`）を設定します。
  * **書式**: `,SEQUENCE, [ステップキー], Com_Mode, "[通信条件]", "[フロー制御]", "[送信デリミタ]", "[データモード]"`
  * **指定例**: `,SEQUENCE, 10, Com_Mode, "$BAUD$,$PARITY$,$DATA_BITS$,$STOP_BITS$", "$FLOW_CTRL$", "$TX_DELIM$", "$DATA_MODE$"`
* **[Com_Send](./Com_Send.Md)**
  * **概要**: COM ポートへ文字列電文（または通信エラー確認付きファイル）を送信します（0〜3 引数）。通常送信時は第 2 引数に `Sprintf` 書式または改行指定（`"CRLF"` / `"CR"` / `"LF"` / `"NONE"`）、第 3 引数に改行指定を渡せます。第 2 引数 `"FILE"` 指定時はファイル送信後の通信エラー状態（`"CLR"` / `"SET"`）を格納先キーへ保存します。
  * **書式**: `,SEQUENCE, [ステップキー], Com_Send, "[送信文字列またはファイルパス(任意)]", "[Sprintf書式 / 改行指定 / FILE(任意)]", "[改行指定またはエラー格納先キー(任意)]"`
* **[Com_SendFile](./Com_SendFile.Md)**
  * **概要**: 指定した外部テキストファイル（Shift_JIS / CP932）を読み込み、COM ポートへ一括送信します。第 2 引数（`"WaitPrompt"`［既定］ / `"NoWait"` / `"NP"`）で進捗・キャンセルダイアログ表示を制御し、第 3 引数（`true` / `false`）で送信前エラーフラグクリアを指定します。
  * **書式**: `,SEQUENCE, [ステップキー], Com_SendFile, "[ファイルパス]", "[ダイアログ表示モード(任意)]", "[エラークリア(任意)]"`
* **[Com_WaitPrompt](./Com_WaitPrompt.Md)**
  * **概要**: 指定プロンプト文字列（省略時は登録済みプロンプト定義）が受信されるまでアイドルリセット方式で非同期監視待機し、タイムアウト時は指定ラベルへ分岐します（`100` 未満は秒単位換算、省略時は UI 設定使用）。
  * **書式**: `,SEQUENCE, [ステップキー], Com_WaitPrompt, "[待機プロンプト文字列(任意)]", [タイムアウト(msまたは100未満秒)], [タイムアウト時ジャンプ先ラベル(任意)]`
  * **指定例**: `,SEQUENCE, 30, Com_WaitPrompt, ">", 5000, #TIMEOUT_ERR#`
